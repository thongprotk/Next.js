# i18n

## Settings

Source of truth: `src/i18n/settings.ts`

- `languages`: `en`, `vi`
- `fallbackLng`: `en`
- `defaultNS`: `common`
- `cookieName`: `i18next`

## Locales on disk

```
src/i18n/locales/
├── en/
│   ├── common.json
│   ├── home.json
│   └── analytics.json
└── vi/
    ├── common.json
    ├── home.json
    └── analytics.json
```

- One JSON file per namespace.
- **Every key added to `en/<ns>.json` must exist in `vi/<ns>.json`** (and vice versa when editing vi first).
- Namespaces are loaded lazily via `i18next-resources-to-backend` dynamic import.

## APIs

**RSC**

```ts
const { t } = await getServerTranslation(locale, "home");
t("title");
t("greeting", { name: "…" });
```

**Client**

```ts
const { locale } = useParams<{ locale: string }>();
const { t } = useTranslation(locale, "analytics");
```

`useTranslation` syncs `i18n.language` to the URL locale (no browser language detector on the client).

## Paths & switcher

- Links: `getLocalizedPath(locale, "/analytics")` → `/en/analytics`
- Validate: `isValidLocale(locale)`
- `LanguageSwitcher`: writes cookie, rewrites first path segment, `router.refresh()`

## Adding a namespace

1. Create `en/<ns>.json` and `vi/<ns>.json` with the same keys.
2. Pass `ns` into `getServerTranslation` / `useTranslation` on the consuming page.
3. Prefer small, page-scoped namespaces (`home`, `analytics`) plus shared `common` for chrome.
